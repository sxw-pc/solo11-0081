# 离线、安全与合规说明

本文说明 synthlab 如何处理网络、依赖、数据、密钥、路径和预览访问边界。它不是法律意见；若用于受监管环境，仍应由使用方完成自身合规评审。

## 1. 运行期完全离线

synthlab 的运行路径不发起任何出站网络请求：

- 不访问 CDN、云存储、外部 API、远程数据库或包索引；
- 不下载远程词表、模板、字体或前端资源；
- 预览页面的 CSS 内联在 `preview.py`，无 JavaScript、无外链资源；
- 生成、校验、导出只依赖本地文件系统与本地 SQLite；
- 唯一监听的套接字是显式启动的预览服务，固定绑定 `127.0.0.1`；
- 预览服务不把请求转发给任何上游服务。

代码中的 `urllib.parse` 只用于 URL 路径解析与百分号编码，不建立网络连接。测试中的 `http.client` 只连接测试进程自己启动的 loopback 预览服务。

依赖安装不属于运行期：首次安装 `PyYAML` 可能需要包源；在依赖已就绪的环境中，演示、生成、校验和测试均可断网执行。

## 2. 依赖边界

| 用途 | 依赖 | 说明 |
| --- | --- | --- |
| 运行期 | `PyYAML>=6.0` | 唯一的运行期第三方依赖，用于 YAML 解析 |
| 测试 | `pytest>=7.0` | 仅测试期使用 |
| 预览 | `http.server`、`socketserver` | Python 标准库 |
| 数据 | `sqlite3` | Python 标准库，本地文件数据库 |
| 哈希 | `hashlib` | Python 标准库，SHA-256 |
| 序列化 | `json`、`csv` | Python 标准库 |

没有 Web 框架、模板引擎、ORM、前端构建链或远程客户端库。

## 3. 数据合规

- `fixtures/` 中所有主体、名称、编号、地址式文本和枚举值均为虚构 fixture。
- 示例邮箱使用保留顶级域 `.invalid`，不对应真实可投递域名。
- 项目不包含真实姓名、身份证号、电话号码、住址、银行卡号、健康记录或其他个人信息样例。
- 项目不包含真实公司名、生产域名、真实公网 IP、主机名或云资源标识。
- 演示中的日期、金额、库存、地区等值由本地固定 seed 生成，不来自真实业务数据。
- 文本词表是本地虚构词表，不抓取语料，不调用模型服务。
- 字段名如 `email`、`full_name` 只表示合成结构的语义，不意味着其中存在真实个人数据。

若使用者把真实数据放入输入或输出目录，该数据的合规责任由使用者承担；本项目不提供脱敏、匿名化、访问控制或留存治理能力。

## 4. 密钥与凭据

项目不写入也不读取：

- API key、访问令牌、密码；
- 私钥、证书、keystore；
- `.env` 凭据、云账号、数据库连接串；
- cookie、会话标识、签名密钥。

预览服务无鉴权设计，因此代码固定只绑定 loopback，且只提供只读 GET/HEAD。不要把预览端口通过反向代理、端口转发或隧道暴露给不可信网络。

## 5. YAML 与输入安全

- 使用 `yaml.SafeLoader` 的受限子类解析；
- 拒绝 YAML 重复映射键，避免“后值覆盖前值”造成静默歧义；
- 只接受声明式数据，不执行 YAML 中的任意对象构造；
- 表名、列名、枚举值、检查表达式均进行结构校验；
- 单表行数默认上限 100000；
- 标识符必须以字母或下划线开头，只包含字母、数字、下划线；
- SQLite 标识符统一引用并转义；
- 输出路径经过输出根目录约束。

YAML 的 `safe_load` 不代表输入一定可信。恶意但语法合法的蓝图仍可能消耗 CPU 或磁盘；本项目未实现资源配额、租户隔离或 DoS 硬化。

## 6. 文件系统边界

- 输出先写入用户指定的 `--out` 目录；
- manifest 中的输出路径为相对路径；
- 预览读取原始文件前，先检查该路径是否在 manifest 输出白名单中，再做安全路径解析；
- 预览只允许访问固定的页面路由、manifest/校验报告和清单内的输出文件；
- `safe_output_path` 拒绝逃逸输出根目录的路径；
- 项目自身不会遍历或上传用户文件。

## 7. 可复现与可审计

- 同蓝图、同 seed、同版本产生相同内容；
- 种子由 SHA-256 派生，不依赖全局随机状态；
- manifest 记录蓝图哈希、表统计、表数据哈希、输出文件哈希和内容指纹；
- 内容指纹排除时间戳；
- verifier 从磁盘重读 manifest、蓝图和数据文件，独立重算约束、哈希和指纹；
- SQLite 导出后执行外键与完整性检查。

审计建议：

```bash
python -m synthlab demo
python -m synthlab verify --out out/demo
cat out/demo/manifest.json
cat out/demo/verification.md
```

跨 SQLite 运行库版本时，SQLite 文件字节可能不同，因此跨版本内容指纹不作保证；蓝图、表数据和文本导出仍可分别复核。

## 8. 预览访问控制

`python -m synthlab serve --out out/demo` 的行为：

- `create_server` 硬编码 `("127.0.0.1", port)`，不读取可配置监听地址；
- 不提供 `0.0.0.0` 或局域网绑定选项；
- 只实现 GET / HEAD；
- POST / PUT / PATCH / DELETE 先丢弃请求体，再返回 405，避免半包连接问题；
- HTML 动态值经过 HTML 转义；
- 不提供文件上传、删除、写入或执行功能；
- 仅适合本机开发预览。

它不是生产服务器：没有 TLS、鉴权、CSRF 防护、速率限制、访问日志轮转或多租户隔离。

## 9. 已知非目标

以下内容不在合规承诺内：

- 真实数据脱敏或匿名化；
- GDPR、HIPAA、PCI DSS 等特定法规认证；
- 密钥管理、加密静态存储或传输加密；
- 不可信多用户沙箱；
- 远程数据源访问与远程数据库连接；
- 对生成内容作事实真实性或业务合理性保证。
